2. Fetch the session branch and extract only the restore package into a

```bash

```

3. Require `"ok": true`, `"total_rows": 39269`, `"integrity": "ok"`, and
   `"fk_violations": 0` in the output. Keep the printed `backup_path`.
4. Re-enable/reload the PythonAnywhere web app. Sign in with an original
   account and check clients, sales, bookings, payments and balances.

The script uses only Python's standard library. For an existing runtime DB,
it imports into a disposable staging copy and checks every snapshot value
before publishing. It takes a SQLite-consistent backup of the runtime DB
first. SQLite backup publishes the staged data transactionally; it does not
copy bytes over an open database or leave a stale WAL next to a replaced file.
The adjacent `*.legacy-20261020-restored.json` receipt blocks accidental
re-runs that could erase later transactions. No startup hook, recurring sync,
or automatic database overwrite was installed.

If staging fails, leave the web app stopped, investigate the error, and keep
the original runtime DB; it has not been replaced. Do not delete a receipt to
force another production restore without reviewing all newer server data.
